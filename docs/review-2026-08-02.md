# Full review, 2026-08-02

A phased review of the codebase, the installer, the docs and the UI, run before
widespread use. Six review passes (agent decision path by hand; tray, HID/decode,
CLI/sampler, installer, and docs-vs-code fanned out), findings verified against
the source before anything was fixed, fixes landed as atomic commits with
red-green tests where the code is testable. Roughly forty findings; the ones
that mattered are below.

Everything in "Fixed" is committed. "Deliberately not fixed" continues the list
started in status.md. "Open" is what needs a human, hardware, or an opinion.

## Fixed: could have shut the machine down wrongly, or failed to

- **`Instant::now() - duration` panics inside the boot window.**
  `Instant` on Windows counts from boot, and the agent subtracted 60 s at
  startup, the sampler 15 s. Both are boot-started, so either could die on
  arrival on a fast boot, silently. All sites now use `Option<Instant>` where
  `None` means "due now". *(Not unit-testable without mocking the clock; the
  subtraction is simply gone, and the panic is documented std behaviour.)*
- **A shutdown could fire against fresh mains readings.** The outage latch
  outlives the outage by up to a debounce, and the thresholds and the backstop
  kept evaluating inside that tail. A qualifying streak begun during the outage
  could complete there — with `warn_before_s = 0` (which `validate` allows)
  that is a machine shutting down seconds after power returned. The backstop
  had the same hole after a sleep that spanned the end of an outage. Policy now
  refuses to *newly* fire while the last believed status is mains and the
  device is answering; staleness re-arms the backstop. Pinned by three tests.
- **`shutdown_on_wake` could never fire.** It set the commitment directly and
  the very next pass observed a non-shutdown action and cancelled it — the log
  would have read "woke onto battery, shutting down" then "shutdown cancelled",
  every time. Rewired through the policy as `Why::Wake` with a bounded
  attribution window; a user-present resume retracts it, mains retires it, and
  the normal announce/grace/cancel machinery applies. Five tests.
- **The disconnected path announced a shutdown and executed nothing** — and was
  unreachable anyway, because nothing ever set `device` back to `None` after
  the first open, so "lost the UPS" and the reconnect backoff were dead code. A
  dead handle rode the input-retry path (up to an hour blind). The loop now
  falls through while disconnected into the same grace/execute machinery, with
  `execute_os_only` when there is nothing to arm, and five consecutive failed
  status polls declare the handle dead and reopen.
- **Input report 20 fabricated an outage.** `HidP_GetUsages` cannot report
  usages a report does not contain; report 20 carries exactly two flags, so
  decoding it as a full `PresentStatus` read `ac_present` as cleared, and
  `on_battery()` is `!ac_present || discharging`. A report-20 push with flags
  *clearing* (battery recharging past the capacity limit, on healthy mains) hit
  all three consumers: the agent latched a phantom outage, the tray flipped to
  "On battery", the sampler wrote a phantom row. The two flags are now merged
  into the held status.
- **`--set 66` bypassed the arming guard.** Report 66 is the standard
  `DelayBeforeShutdown` declared a second time, and mirror pairs on this unit
  are write-equivalent. The guard covers it now, as a named function with a
  test that walks every countdown register.

## Fixed: wrong numbers, lost evidence, missed warnings

- **The agent's shutdown warning could be starved.** The tray only read the
  agent's status file when the *device* snapshot changed, and an armed pending
  shutdown changes nothing the device reports — on a smoothed, steady
  on-battery reading, the toast and red countdown could arrive after the
  machine began going down. A one-second timer now polls unconditionally.
  Related: a `pending` record of any age was trusted, so an agent killed
  mid-grace left a red countdown forever (now: newest file younger than 20 s
  wins, which also stops a stale machine-wide record shadowing a live per-user
  agent); the warning's sequence number was marked seen before the toast
  actually displayed (now: seen means delivered, failed toasts redeliver); and
  nothing retried `NIM_ADD` after a failed add, leaving an invisible tray for
  the whole session (now retried from the timer).
- **The agent's numbers had no age.** Report 12 failing while report 22 kept
  answering left a days-old runtime qualifying the thresholds as current. Aged
  out past the staleness window; the backstop covers what remains.
- **The sampler missed every transition once the input stream died** — which is
  the documented permanent state after Windows binds its battery driver, i.e.
  after PowerChute is removed. The sweep already read the status; it now feeds
  the same transition diff, so onbattery/online rows land with at most a sweep
  of latency. A failed CSV append also no longer throws the window away (a
  SYSTEM task's stderr goes nowhere), and the self-test path no longer sweeps
  twice into one event row.
- **An armed shutdown announced itself twice** (two `Event::Shutdown` publishes
  per pass, two sequence bumps, two toasts), and an aborted one still announced
  "shutting down now". One announcement now.
- **Tray replug blindness and twitch.** A re-enumerated UPS sat behind the
  60 s input-retry cadence instead of the 1–15 s reconnect backoff (two silent
  sweeps now reopen the handle), and the sweep wrote raw quantised readings
  over the smoother's output once per sweep.
- **Missed "Power restored".** An outage that ended while the device was
  unreachable was announced as "UPS responding again"; a remembered outage now
  gets its all-clear. DPI/theme changes also now repaint immediately, teardown
  stops the device thread before the window dies, and bad CLI arguments exit 2
  instead of silently doing something else (`--interval abc` sampled at 300 s;
  `--read 21,300` dropped the 300).

## Fixed: the installer

- **`-Service` under Windows PowerShell 5.1 ended with no agent at all.**
  PS 5.1 passes embedded quotes to `sc.exe` un-escaped, shredding the image
  path at the space in `Program Files` — and the working scheduled task had
  already been unregistered. Now `New-Service` (a .NET string, no re-quoting),
  and the task form is removed only after the service exists and started.
- **A custom `-LogDir` wrote a config the agent never read.** The installer
  advertised `D:\upslogs\jdups.conf`; the agent's search never looks there, so
  `armed = true` in the advertised file did nothing, permanently — the exact
  "believed protected" failure the project exists to avoid. The agent now gets
  `--config` explicitly, and the final `--check` uses the same file.
- **`-Agent` over a `-Service` install left both forms fighting the singleton**
  at every boot; the task branch now removes a leftover service.
- **The failure actions never ended.** PowerShell ate the `""` that stops the
  SCM repeating the last action, so "restart twice then stop" was "restart
  every 60 s forever" (or nothing, unchecked). Quoted as one token, verified to
  pass verbatim under both 5.1 and 7, exit codes checked.
- **Uninstall could report success with both SYSTEM tasks still registered**:
  unelevated `Get-ScheduledTask` silently omits them, and the elevation
  heuristic trusted it. It now probes the task files, where access-denied means
  "exists, needs elevation". Also: the tray now gets a real `WM_CLOSE` via its
  window class in both scripts (its only window is hidden, so
  `CloseMainWindow()` never worked and every upgrade left a ghost icon), a
  declined UAC prompt says so instead of throwing, `-SamplerOnly -Agent` is
  refused, trailing backslashes in dir parameters no longer corrupt command
  lines, uninstall removes the tray's `AppUserModelId` key, and the final
  report distinguishes dry run from "the agent refuses its config and is
  crash-looping".

## Deliberately not fixed (adds to the list in status.md)

- **Mains returning seconds after an armed commit does not unwind.** The cancel
  arm logs but cannot abort Windows or disarm the UPS once `execute` has run.
  The window is `OS_GRACE_S` (10 s) against a mains-return debounce of at least
  5 s, so it is unreachable at the default `debounce_s = 20`; the cost when
  reachable is one clean reboot cycle, not data loss. An unwind here would
  touch the most dangerous code in the project to save a reboot in a
  configuration nobody ships. Revisit if `debounce_s < 10` ever becomes normal.
- **`ShutdownImminent` is trusted from a single read.** Deliberate: it is the
  device announcing its own output cut, and second-guessing it loses the race
  it exists to win.
- **The outage latch is not persisted across an agent restart.** An agent that
  crashes and restarts mid-outage re-learns on the next fresh reading within
  seconds; persisting the latch buys almost nothing against the staleness and
  settle machinery it would have to bypass.
- **A sampler started mid-outage writes no `onbattery` row** (there is no
  previous status to diff against). The `ac` column carries the state; the
  event pairing is recoverable.
- **Two `raw.rs` timeout-boundary cases**: an input report completing exactly
  at the timeout is consumed and discarded (≤ one poll of latency, exact-race
  only), and the `wait()` catch-all error arm skips the cancel-and-drain
  (reachable only if `WaitForSingleObject` itself fails). Both are in
  measured-against-hardware I/O code; not worth destabilising for.
- **Multi-user task-name collisions** (`-PerUser` for two users fights over
  flat task names) and **custom `-InstallDir` uninstall** (binaries stranded;
  uninstall only knows the defaults). Real, small, single-user machines
  unaffected. Documented here instead.
- **Install verification cannot catch the dev-tray singleton trap** (installed
  tray exits 0 instantly if a dev tray holds `Local\jdups-tray-singleton`).
  Known trap, documented in status.md and CLAUDE.md.

## Asked and answered (owner decisions, 2026-08-02)

- **No toast on the alarm toggle.** User-initiated, instant, and the checkmark
  already shows the readback; notifying someone of a thing they just did is
  noise. The misclick concern stays covered by the menu layout alone.
- **No repeated shutdown warning** at 30 s / 10 s. Once is the design.
- **No distinct failed-retrying tray state** after an aborted transaction; the
  30 s retry resolves it soon enough.
